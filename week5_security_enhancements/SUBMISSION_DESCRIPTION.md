For my Week 5 task, Security Enhancements in Python Applications, I developed SecureNotes, a local Python notes CLI that handles user accounts, passwords, private notes, imports, exports and backups. Instead of only adding security features to finished code, I preserved a small intentionally vulnerable baseline, reviewed it through a threat model and data-flow analysis, and demonstrated the impact of each weakness locally with synthetic data. The audit identified eleven vulnerability classes: SQL injection, unsalted MD5 password storage, broken object-level authorization, plaintext notes, predictable raw sessions, unsafe pickle deserialization, path traversal, OS command injection, account enumeration without lockout, sensitive errors/logs and missing input limits. I then implemented a separate hardened application using parameterized SQL, owner-scoped queries, PBKDF2-HMAC-SHA256 with 600,000 iterations and per-user salts, password-derived Fernet encryption, random hashed expiring sessions, generic authentication errors, account lockout, strict validation, safe file paths, JSON-only imports, SQLite’s backup API and redacted audit events. Bandit reported seven issues in the baseline and none in the secure package after one documented false-positive triage. A paired attack harness shows all thirteen vulnerability checks exploitable or exposed before hardening and blocked or protected afterwards, while legitimate reading and backup workflows still succeed. The final suite contains 58 passing tests. The GitHub repository contains the secure source, quarantined baseline, tests, threat model, complete security audit, attack transcripts, Bandit reports, figures and reproduction instructions at the repository root. This project taught me that secure coding means controlling every trust boundary—SQL, identity, ownership, cryptography, serialization, filesystem, shell and logging—rather than relying on a scanner or a single library.
